### P0 回归修复：rewind 死锁（本次审查发现）

`session_runtime_operations` 的 P0 并发修复（load/new 全程持有
`runtime_transition_guard`）与 `SessionRewindExecution::execute` 已有的同域
guard 形成**不可重入锁二次获取死锁**：rewind 执行成功后的重放路径
`start_load → prepare → runtime_transition_guard()` 永久等待自身持有的锁，
导致两个 rewind 测试超时挂死（此前全量测试被挂死进程掩盖，未暴露）。

修复（`session_rewind_execution.rs`）：`mark_effect_confirmed` 后、`start_load`
前显式 `drop(_runtime_guard)`——rewind 保护段随 effect 确认结束，由 replay
load 无缝接管 per-chat 互斥。注释记录死锁成因。

### P1 断言遗漏：persist 失败不广播（计划内但执行遗漏）

`audit-fix.mjs` 记录「问题 2 persist 失败不广播 + 重试缓冲（同步调整受影响
的测试断言）」，但执行时未调整 `retryable_prompt_persist_failure_terminalizes_
broadcast_turn_without_dispatch` 断言。新语义（客户端不得先于镜像看到未持久化
状态；更新入重试队列，成功后再广播）下，persist 失败时任何 turn 状态均不广播，
镜像停留 base snapshot。断言由 `Some("failed")` 改为 `None`，契约不变：
UI 绝不会把未投递 prompt 显示为 active。
